# 内容补充设计：城市、搜刮、任务地形与列车-尸群冲突

> 文档状态：草案 v0.1（2026-08-01 讨论结论整理）
> 关联文档：[GAME_DESIGN.md](GAME_DESIGN.md)（主线循环、关注度、后方尸潮）、
> [TECHNICAL_ARCHITECTURE.md](TECHNICAL_ARCHITECTURE.md)（模块边界与适配原则）、
> [COMPATIBILITY.md](COMPATIBILITY.md)（模组兼容基线）
> 待办：作者尚有一批踩过的坑未整理，见 §7 等待补充。

本文档不重复既有文档中的任务状态机、关注度、后方尸潮和性能预算，只补充
"内容生成与冲突层"的设计结论：

1. 城市如何定位，车站如何保证落在城市里；
2. 城市搜刮与战利品如何自然生成；
3. 任务依托的地形要不要预先建造；
4. 丧尸如何与列车形成真正的冲突，避免"开车看风景"；
5. 失落城市原版铁轨与 Create 铁路的冲突处理。

## 1. 总原则：不拼模组，分层集成

世界内容由三个独立层组合，`lasttrain` 作为导演层在上方协调：

| 层 | 负责 | 提供方 |
| --- | --- | --- |
| 城市内容层 | 城市本身（建筑、道路、内部废墟铁轨、战利品） | 失落城市自动生成，位置由 lasttrain 指定 |
| 线路内容层 | Create 轨道、车站、桥梁、隧道 | 通达铁路（或自有 RouteBackend） |
| 导演层 | 城市选择、车站吸附、任务挂接、尸潮导演、存档 | lasttrain 核心模组 |

任何一层都不被允许"直接拼上就完事"：

- 城市位置是战役剧本（预定义），城市内部结构是程序生成（失落城市）；
- 车站必须吸附到城市锚点（本章 §2）；
- 任务地形是可复用模板的程序组合（§4）；
- 原版铁轨与 Create 轨道的冲突用世界观解决，不做强行替换（§6）。

对齐技术架构的原则：核心模块不通过 Mixin 或反射修改通达铁路私有生成器；
确需访问内部实现的原型代码放入独立、版本锁定的兼容层 jar。

## 2. 城市定位与"车站必在城里"

### 2.1 城市位置：失落城市预定义城市球

失落城市（Lost Cities，1.21 NeoForge）提供 datapack 注册表
`lostcities:predefinedspheres`，JSON 放在
`data/<命名空间>/lostcities/predefinedspheres/*.json`，字段如下：

```json
{
  "dimension": "minecraft:overworld",
  "chunkx": 100,
  "chunkz": 200,
  "centerx": 1612,
  "centerz": 3212,
  "radius": 100
}
```

| 字段 | 含义 |
| --- | --- |
| dimension | 城市所在维度 |
| chunkx / chunkz | 城市中心所在区块坐标 |
| centerx / centerz | 城市中心的方块坐标 |
| radius | 城市球半径（方块） |

关键性质：

- 预定义球优先级高于随机城市球；
- 配置 `CITYSPHERE_ONLY_PREDEFINED` 开启后，世界只生成预定义城市；
- 城市球判定与区块生成顺序无关，同一坐标在任何服务器/存档顺序下结果一致；
- 相邻球有确定性防重叠逻辑。

设计结论：**城市 JSON 就是战役的剧本骨架**。起点城、支线城、中转站、
最终隔离站全部由坐标表定义；城市内部内容仍由失落城市自动生成。这既保留
了"手绘路线"的叙事控制，又不需要手工建造地图。城市列表同时承担章节
结构：每座城挂天数窗口、任务类型和物资曲线（对齐 GAME_DESIGN §7）。

### 2.2 车站吸附：保证车站落进城市

通达铁路现状：`StationPlanner.generateStation` 按区域用低差异序列均匀选点、
过滤海洋、德劳内三角网连线；**没有外部指定站点位置的 API**。

按优先级采用三条路线：

1. **上游合作（首选）**：向通达铁路作者提交 PR，增加"外部站点提供者"
   接口。作者已有 `ITrackPreGenExtension` 这类扩展点先例，且只维护
   1.21.1 NeoForge 单版本，合作成本低。
2. **版本锁定兼容层（原型）**：在独立兼容 jar 中用 Mixin 把 `generateStation`
   的选点结果吸附到预定义城市球心。仅用于验证玩法；注意通达铁路为
   GPL-3.0，对外分发修改版需连带开源，Mixin 分发授权上偏灰，发布前需与
   作者确认或改为 fork/PR 路线。
3. **自有 RouteBackend（兜底）**：lasttrain 自己定站、用 Create 轨道 API
   （`BezierConnection`，通达铁路内部同款）铺轨；通达铁路只提供荒野支线
   或直接关闭其车站生成。

验收标准：每个预定义城市球内至少一个主线车站；城市球内不出现通达铁路
随机车站；线路从城市一侧进入、另一侧离开。

## 3. 城市搜刮与战利品

### 3.1 失落城市现成骨架

- 城市箱子走 `lostcities:chests/lostcitychest`、`raildungeonchest` 战利品表；
- 城市区块带有 `cityLevel`（城市等级），越靠近市中心/越深越高——这是现成的
  "越危险越富"曲线；
- 条件系统（如 `chestloot`）控制容器生成，可数据驱动调整。

### 3.2 lasttrain 的注入

- 用 datapack 覆写/扩展战利品表，注入战役物资：列车燃料、维修件、任务
  道具、稀有升级件；
- 物资按城市等级分档投放；稀有升级遵循"每队一份"原则（对齐
  GAME_DESIGN §6.5）；
- 不通过调爆率制造末日感。末日感来自"停车时间成本 + 背包上限 + 尸潮
  压力"：每次进城都是一次有限窗口的回收行动。

建议的搜刮节奏（一次城市停车战役）：

1. 沿街表层：食物、弹药、零件（快，低风险）；
2. 建筑内部：医疗、燃料、工具（慢，室内伏击风险）；
3. 地下/工业区：高级升级件、任务组件（长停留，触发防守波次）。

## 4. 任务地形：不预先建地图，预制"乐高块"

回答"要不要预先建造"：**不建整张地图**。预先建造的只有两类小资产：

1. **可复用损坏模板**：断桥、塌方隧道、堵轨废车、封锁站门、停电设施、
   站台尸巢等，建议 30×30 以内的 NBT 结构 + JSON 定义（参考通达铁路
   `railway_structure` 的桥/隧道/车站模板格式）；
2. **城市内固定任务锚点**：直接挂在预定义城市球坐标上，不额外生成。

线路导演的放置流水线：

```text
铺设区段 → 扫描线路 → 选择剧情锚点 → 放置损坏模板
→ 登记任务（一次性操作凭据） → 验证净空与轨道连通 → 挂通行锁
```

模板与任务类型一一对应：断轨=断轨模板+状态机；塌桥=塌桥模板+清障任务；
封锁站门=站门模板+供电任务。世界因此是"模板的程序组合"，而不是手搓的
固定地图，同时每个模板都能复用、验证和存档。

## 5. 丧尸 × 列车：冲突设计（结论版：停车主战场）

### 5.1 核心结论

**别做"丧尸爬车"通用机制。丧尸与列车的冲突全部收敛到"停靠决策"上。**

- 列车不负责与丧尸正面战斗；列车负责制造时间压力与"车内回合"。
- 丧尸的核心功能是逼玩家做决定：停不停、停多久、搜多深。
- "开车看风景"由车内运营与驾驶成本解决，不依赖丧尸追车。
- 登车只作为稀有高潮事件（剧情节点/特定防守波次），每场战役有限次数，
  不做通用机制。

参考依据：

| 游戏 | 借鉴点 |
| --- | --- |
| The Final Station | 车上管理（资源/幸存者）与站台搜刮两阶段循环 |
| 地铁：离去 | 列车=移动基地；停靠站=章节；搜刮-制作-推进 |
| 往日不再 | 载具双状态（燃料+维修）；尸潮=可惹可躲的世界威胁 |
| 求生之路 | AI Director 节奏；特感有明确对策 |
| 七日杀 | 天数驱动的尸潮升级与防守波次 |

### 5.2 三层冲突模型

1. **移动中＝车内回合（不战斗）**：驾驶操作（速度/坡度/制动/燃料）、
   整备（制造、维修、医疗、物资整理、升级选择）、前方预警与停靠决策。
   参考《地铁：离去》的车上基地运营。
2. **停靠时＝主战场（下车战斗）**：尸潮围站、堵门、守点；复用现成怪物
   寻路与波次系统；特感只在此出现且对策明确（L4D 式）。
3. **登车事件＝稀有高潮**：剧情节点或指定防守波次触发"车厢内生成事件"
   （破窗登车），每场战役有限次数；物理后端稳定后可升级为真实实体登车
   （能力标志控制），但永远不作为通用日常机制。

### 5.3 追车＝时间压力，不是实体威胁

- 后方尸潮用抽象追击距离（对齐 GAME_DESIGN §5.2）；可见范围只放少量
  实体潮头制造紧张感。
- 追击距离惩罚"停太久/搜太深"，持续行驶拉开距离。
- 不让尸潮实体长期追车，避免性能黑洞。

### 5.4 停车时的威胁清单

- **围站**：站台/城市边缘尸潮随时间升级，逼玩家限时行动；
- **堵门**：搜刮途中出口被尸群或路障封死，需清路突围；
- **守点**：供电、开门、清障类任务的防守阶段（复用任务状态机）；
- **特感**：喷吐者（远程腐蚀车体）、自爆者（近车身爆）、感染者巢
  （堵隧道，任务目标）——每类有明确对策，避免纯数量压力。

夜间车灯、鸣笛、高噪声机械提高关注度并吸引尸潮向停靠点集结，与既有
关注度系统联动——噪声决定"停多久会出事"。

### 5.5 尸潮类型与天数曲线（示例，待数值平衡）

| 阶段 | 天数 | 新增威胁 | 玩家对策 |
| --- | --- | --- | --- |
| 序章 | 1–10 | 蹒跚者：堵轨、围站 | 下车清障 |
| 匮乏 | 11–30 | 疾行者：缩短停车安全窗口 | 控制停车时长 |
| 扩散 | 31–55 | 攀爬者：翻越临时掩体 | 掩体与站位选择 |
| 崩溃 | 56–80 | 破坏者：敲击车体与路障 | 维修件、加固 |
| 最后航段 | 81–99 | 冲刺者：突围窗口极短 | 快速反应、诱饵 |
| 第 100 天 | 100 | 最终潮：全方位围攻 | 全防御手段 |

### 5.6 冲突循环

与 GAME_DESIGN §2 循环对齐，每个线路区段至少包含一次"车内回合"和一次
"停靠主战场"：

```text
行驶整备 → 前方预警 → 停靠决策 → 下车搜刮/任务
→ 被围 → 突围 → 发车 → 行驶整备
```

### 5.7 技术要点

- 登车事件＝"车厢内生成 + 防守阶段"，不依赖移动碰撞绑定；
- 车体损伤以逻辑耐久（Campaign/Vehicle SavedData）为事实来源；
- 追击距离抽象 + 可见潮头，遵循性能预算（对齐技术架构 §13）；
- 特感与防守波次复用任务状态机的防守阶段；
- 物理后端稳定后，登车可升级为真实演出（能力标志控制），不进 MVP。

### 5.8 MVP 边界

- MVP 只做：停车围攻 + 追车倒计时（两件都能用现有技术立起来）；
- 登车事件列入后期里程碑，作为演出彩蛋而非核心循环。

## 6. 失落城市原版铁轨与 Create 铁路的冲突

失落城市内部的铁路是**原版铁轨 + 矿车车站**，与 Create/Aeronautics 物理
列车不兼容。决策：**不做替换，把旧铁路当"旧世界废墟"保留**。

- 旧地铁口、断裂铁轨、废弃矿车是现成的场景资产和叙事素材；
- 玩家任务不是"修旧铁路"，而是在废墟上重建 Create 铁路：通达车站建在
  旧站台旁或城市边缘锚点；
- 可选配置：失落城市的 `RailSettings`/railway parts 可关闭内部铁轨生成、
  只保留站台废墟，避免视觉打架；
- "恢复站台供电/闸门"类任务可围绕旧站台展开，强化新旧世界的对比。
