# 末班列车：百日惊变 — 玩法设计文档

> 文档状态：MVP 基线  
> 目标版本：Minecraft 1.21.1 / NeoForge  
> 支持模式：单人世界、单人世界开放局域网、专用服务器  
> 核心依赖：机械动力生态的物理化列车、通达铁路生成的线路载体  

## 1. 游戏概念

玩家共同生活在一列物理化列车上，沿一条持续向前生成的铁路穿越废弃车站与丧尸城市。列车既是载具，也是唯一可以长期经营的移动基地。玩家必须停车搜刮和维修，但每次停车都会让尸群逐渐包围列车；继续前进能够甩开普通尸群，却会消耗燃料、零件和食物。

一局标准战役持续 100 个游戏日。队伍需要在第 100 天前维持列车运转、完成线路障碍、升级车厢并抵达最终避难枢纽。通关后可以选择结束战役，或保留世界进入难度持续上升的无限模式。

### 1.1 设计支柱

1. **列车就是家**：重要制造、储存、复活与升级能力都依附于列车，失去列车等于失去长期生存能力。
2. **停靠带来机会与危险**：最好资源位于车站和城市，停车时间越长，敌人压力越高。
3. **前进不可替代**：后方尸潮和资源衰减阻止玩家永久定居，但不会用不可逆方式直接摧毁存档。
4. **合作但不锁职业**：玩家可以自然分工为司机、机械师、探索者、守卫和医护，任何人都能临时接替。
5. **随机但可恢复**：任务、地点和奖励具有随机性；主线目标必须可验证、可重载、可补发，不能因随机生成或物品丢失永久卡关。

### 1.2 标准游玩规模

- 平衡基准：1–6 人。
- 可运行目标：1–8 人。
- 单人获得较低任务用料、较少敌人和较宽松的交互时间，不需要操作多个角色。
- 服务器只在至少一名非旁观者玩家在线时推进战役日历和任务计时。

## 2. 核心玩法循环

一轮循环以一个“线路区段”为单位，目标时长约 15–30 分钟：

1. **行驶与侦察**：司机控制速度，队员通过无线电、地图和前方信号获知地点与异常。
2. **做出停靠决定**：主线障碍必须处理；普通车站、城市支线和求救信号可以跳过。
3. **建立临时安全区**：制动、确认撤退路线、布置照明和防御，必要时留下守车人员。
4. **探索与搜刮**：在站点或城市取得燃料、食物、药物、弹药、铁路材料和车厢升级件。
5. **完成任务**：修轨、供电、解锁闸门、清障或启动设备。高噪声操作通常触发防守阶段。
6. **撤回与发车**：队员回到列车，解除制动并驶出危险区；落单玩家可通过有限的追车或救援机制回归。
7. **行驶中整备**：治疗、整理物资、制造零件、修理列车和选择下一项升级。

循环中的核心权衡为：

- 多搜刮一栋建筑，可能获得稀有物资，也会增加停车时间和尸群强度。
- 增加功能车厢能提高生产与储存能力，也会增加重量、燃料消耗、制动距离和噪声。
- 高速行驶更容易拉开尸潮距离，但会增加线路事故风险与燃料消耗。
- 跳过可选站点可以节省时间，但会让后续强制障碍缺少材料。

## 3. 世界与线路结构

### 3.1 主线模型

- 世界中存在一条具有明确“前进方向”的主铁路。
- 通达铁路负责提供轨道、站台等线路载体；本项目的线路系统负责连续性校验、区段编号、事件挂接和存档状态。
- 每个区段拥有稳定 ID、世界种子派生种子、里程范围、地点类型和任务状态。
- 列车前方至少预生成若干安全距离的区段，后方区段可以正常卸载，但其任务和搜刮状态必须保存。
- 生成器不得让必经主线出现没有任务解法的断头路。自然断轨只有在任务导演明确选择“断轨事件”时才允许出现。
- 城市是铁路附近的探索区域，不要求所有建筑与铁路直接相连；车站是任务、补给和存档锚点。

### 3.2 地点类型

| 地点 | 主要产出 | 主要风险 | 是否可跳过 |
| --- | --- | --- | --- |
| 小型站 | 食物、基础零件、地图信息 | 少量感染者 | 是 |
| 货运站/编组场 | 燃料、钢材、可回收车厢 | 开阔区域、重型感染者 | 是 |
| 城市站 | 综合物资、任务入口 | 高密度尸群 | 视任务而定 |
| 医院区 | 药品、复活/医疗升级 | 室内伏击、特殊感染者 | 是 |
| 工业区 | 高级机械件、发电设备 | 噪声事件、污染 | 是 |
| 军事检查站 | 武器、弹药、装甲 | 高强度敌人、封锁门 | 是 |
| 隧道/桥梁 | 线路通行 | 视野差、坍塌或守点 | 主线时否 |
| 避难枢纽 | 章节和最终目标 | 大规模围攻 | 否 |

### 3.3 生成保障

- 新区段在列车到达前完成轨道连续性和净空检查。
- 必做任务的目标方块、交互设备和关键容器不得被普通爆炸或玩家误拆永久删除；被破坏后应重建或提供替代交互。
- 每个主线障碍至少有一种不依赖随机战利品的保底解法。
- 最终避难枢纽在战役进入最终阶段后生成于前方可达区段，不替换已经被玩家探索的区块。

## 4. 开局流程

### 4.1 首次世界初始化

首次启动世界时，服务器执行一次幂等初始化：

1. 选择并锁定起始区段。
2. 生成默认起点站、主线出口和周边教学区域。
3. 生成并组装默认物理列车。
4. 将列车、起点站和战役记录绑定到同一个队伍 ID。
5. 放置按初始队伍人数计算的补给。
6. 创建教学任务并保持出站信号关闭。

初始化具有唯一完成标记。服务器崩溃或重启后只能继续未完成步骤，不得重复生成列车和补给。

### 4.2 默认起点站

起点站至少包含：

- 安全出生区与队伍集合点；
- 站务室/无线电，用于显示战役说明和当前目标；
- 基础维修台与少量铁路材料；
- 初始补给仓；
- 受任务控制的站台闸门或出站信号；
- 默认列车停放与检查区域；
- 无法依靠拆站获得大量高级材料的保护或替代方块规则。

### 4.3 默认列车

MVP 默认列车由三个功能单元组成：

1. **动力/驾驶单元**：驾驶位、制动控制、燃料或动力接口、列车状态显示。
2. **工坊/货运单元**：基础制造、维修工具、初始物资和任务材料储存。
3. **生活/医疗单元**：床位或复活锚点、食物、基础治疗与玩家安全重连点。

默认列车必须满足：

- 单人可以从任意关键操作位完成发车、停车和基础维修；
- 其他玩家可以接管驾驶，不绑定唯一司机；
- 关键控制被破坏后可使用起点站或已激活车站的蓝图恢复；
- 列车质量、损伤、燃料、速度和制动状态可以被玩家清楚读取；
- 新增车厢不会绕过质量、动力和制动成本。

### 4.4 初始补给

初始物资采用“队伍基础量 + 每名玩家增量”，按初始化时 1–6 名玩家计算并设置上限，避免反复进出服务器刷物资。目标储备为：

- 每人约 2 个游戏日的基础口粮；
- 每人一套基础近战与照明工具；
- 足以治疗数次普通受伤的公共药品；
- 完成教学维修后仍有少量余量的轨道和机械材料；
- 足以行驶到前两个补给点的燃料；
- 少量防卫资源，不足以长期清空整座城市。

后加入玩家只领取个人基础工具包，不重复增加公共燃料和稀有物资。

### 4.5 教学任务：“最后一次发车”

教学任务控制在 10–20 分钟：

1. 在站务室接收无线电广播；
2. 检查动力、制动和车厢连接；
3. 从维修库取得保险件，恢复站台供电；
4. 启动出站信号/打开站门；
5. 抵御一次短暂的小型尸群；
6. 全员或单人确认发车，驶过第一个里程标；
7. 解锁正常任务导演与战役日历。

教学中的关键物品可以重新领取；互动提示需要同时支持单人和多人，不要求多人同时按键。

## 5. 生存压力

### 5.1 尸潮关注度

战役维护一个 0–100 的“关注度”：

- 停车、枪声、爆炸、高噪声机械和任务设备会提高关注度；
- 持续向前行驶会逐渐降低关注度，但不能低于当前章节的最低值；
- 高关注度提高生成频率、特殊感染者概率和登车事件概率；
- HUD 使用描述性等级显示：安静、受注意、聚集、围攻、失控。

关注度是对玩家行为的即时反馈，不代替随天数增长的基础难度。

### 5.2 后方尸潮

- 后方尸潮以抽象“追击距离”表示，不需要永久模拟数千个实体。
- 长时间停车会缩短追击距离，行驶会拉开距离。
- 距离归零时触发高压围攻，而不是无预警地删除列车或世界。
- 完成围攻、成功发车并持续行驶后可以恢复距离。
- 服务器无玩家在线时追击距离不变化。

### 5.3 人数缩放

- 敌人数量、任务用料和防守时间按“近期活跃人数”缩放。
- 活跃人数每 5 分钟采样一次并平滑变化，避免玩家临时退出降低当前任务难度。
- 单人优先缩短同时互动要求和守点时间；多人主要增加敌人入口和总量，不简单增加敌人生命。
- 任务奖励按活跃人数提供基础补给，但稀有升级原则上每队一份。

## 6. 任务导演

### 6.1 目标

任务导演负责在可控节奏下选择地点、障碍和奖励。所有决定由逻辑服务器做出，并在区段生成时写入存档。重新登录、开放局域网或重启专用服务器不得重抽任务。

导演的输入包括：

- 战役日数和章节；
- 已前进里程与连续停车时间；
- 近期活跃人数；
- 当前资源压力的粗粒度指标；
- 最近任务类型及成功/失败记录；
- 当前关注度与追击距离；
- 可用地点模板和线路生成结果。

导演遵守以下约束：

- 同时只能有一个阻止主线通行的强制任务；
- 不连续选择相同的主线障碍；
- 不在未完成防守阶段时于同一区域叠加第二个强制防守；
- 队伍连续失败后选择较短或有额外保底物资的任务；
- 关键剧情地点必须在规定天数窗口内出现；
- 可选任务不得永久封锁主线。

### 6.2 任务状态机

所有任务使用统一状态机：

`已计划 → 已通告 → 已激活 → 目标执行 →（可选）防守 → 已完成`

旁路状态包括：

- `已失败`：可选任务超时或目标被放弃；
- `等待恢复`：检测到目标缺失、区块异常或关键物品丢失；
- `已跳过`：队伍明确放弃可选任务；
- `已补偿完成`：管理员或自动恢复系统确认无法修复并发放最低必要结果。

每次状态变化保存任务 ID、时间、操作者、目标进度和生成对象引用。

### 6.3 主线障碍池

#### A. 铁路断开

1. 信号提前警告并要求停车；
2. 检查点显示需要修复的轨道段；
3. 附近维修棚提供最低保底材料，高级材料可缩短修复时间；
4. 玩家铺设/焊接并由任务系统验证连续性；
5. 试通电产生噪声，触发短时防守；
6. 轨道验证通过，信号转绿。

#### B. 车站供电与闸门

1. 关闭的站门或道口设备封锁主线；
2. 玩家寻找保险件、燃料或电缆并恢复发电机；
3. 启动控制室中的若干开关；
4. 开门过程持续一段时间并吸引尸群；
5. 门完全打开后任务完成，之后不能因重载再次关闭卡住列车。

#### C. 隧道/线路清障

1. 隧道口检测到坍塌、废车或感染巢；
2. 玩家选择消耗炸药快速清理，或使用工具低噪声慢速清理；
3. 清理结果需要通过列车净空检查；
4. 撤除临时障碍并恢复信号。

#### D. 道岔与信号修复

1. 故障道岔默认导向不可通行线路；
2. 队伍修复线路箱并到两个位置确认信号；
3. 单人模式允许按顺序完成，多人可以并行；
4. 状态锁定后允许列车通过。

### 6.4 可选任务池

- 搜救幸存者：在时限内找到目标并护送至列车或安全站点；
- 回收车厢：修复并连接功能车厢，承担额外重量风险；
- 医疗急需：进入医院取得药物，换取医疗设施升级；
- 失联补给队：追踪无线电信号，获得燃料或弹药；
- 水塔/燃料站重启：防守设备并获得一次大额补给；
- 清理仓库：消灭区域威胁或保持控制，解锁高价值容器；
- 黑匣子/日志：收集世界背景，并为最终枢纽提供可选优势。

可选任务必须在接受前标明主要风险、奖励类别和是否有时限。放弃可选任务不会阻断通关。

### 6.5 奖励原则

- 主线任务保证“继续前进所需资源 + 少量净收益”，不应成为无限刷物资来源。
- 可选任务提供明显净收益或永久升级。
- 连续出现同类资源短缺时，导演提高对应补给地点的权重，但不直接读取或复制玩家每个容器中的精确物品。
- 已领取奖励使用任务 ID 标记，重启后不能重复领取。

## 7. 一百天战役节奏

战役日是独立保存的共享计时。至少一名非旁观者在线时，每 20 分钟累计一个战役日；睡眠用于设置重生和获得休息效果，不跳过战役时间。

| 阶段 | 天数 | 体验目标 | 新增压力与保障 |
| --- | --- | --- | --- |
| 序章 | 1–10 | 学会驾驶、停车、搜刮和维修 | 低关注度；任务材料有明显指引；至少出现一次小站和一次断轨教学 |
| 匮乏 | 11–30 | 建立稳定补给循环，首次扩建列车 | 燃料与药品开始紧张；引入特殊感染者和第一个城市站 |
| 扩散 | 31–55 | 被迫在高风险地区停靠 | 尸潮增长加快；出现复合地点、隧道和较长防守 |
| 崩溃 | 56–80 | 列车维护与路线选择成为核心压力 | 后方追击更强；可出现列车故障、重型敌人和两阶段任务 |
| 最后航段 | 81–99 | 为终局储备并持续向前 | 生成最终枢纽线索；保证关键升级机会；减少低价值重复站点 |
| 第 100 天 | 100 | 抵达并启动最终避难枢纽 | 恢复设施、守住站台、完成最终发车/撤离 |

### 7.1 里程与日数双重推进

- 只躲在起点不能等待最终地点出现：章节关键任务同时要求最低里程。
- 极快推进也不能在前期直接触发终局：高阶段地点受天数窗口限制。
- 当队伍落后计划里程时，导演减少低价值强制障碍并提高燃料保底。
- 当队伍明显领先时，允许更多可选高风险地点，但不通过强制等待惩罚玩家。
- 第 90 天后，最终枢纽保证在前方有限区段内生成，且其位置通过无线电和里程标明确提示。

### 7.2 最终任务

最终任务包含三个可独立恢复的阶段：

1. **抵达**：将列车完整驶入最终枢纽指定站台；
2. **重启**：恢复主电源、通信和站台防御，可通过此前收集的升级降低难度；
3. **守住黎明**：抵御最终尸潮并启动撤离列车/避难设施。

胜利后记录通关天数、里程、任务完成数和列车状态。队伍可以：

- 将世界标记为已通关并继续建造；
- 启用无限模式，使线路继续生成、难度缓慢提高；
- 保留存档后另开新战役。

## 8. 单人与联机设计

### 8.1 统一服务器权威

单人、开放局域网和专用服务器使用同一套逻辑：

- 战役、线路、任务、列车绑定和奖励状态只由逻辑服务器修改；
- 客户端只发送交互请求并显示同步结果；
- 不以某个固定玩家作为队伍进度所有者；
- 世界从单人切换到局域网后沿用原存档，不重置或复制任务；
- 专用服务器重启后恢复相同区段、目标进度、计时和列车引用。

### 8.2 加入、离开与重连

- 首次加入战役的玩家出生在当前列车的有效生活/医疗单元；若不可用，则出生在最近激活的安全车站。
- 重连优先回到安全列车位置，避免加载在已离开的旧区块、方块内部或高速轨道上。
- 掉线玩家不阻止任务完成和发车。
- 任务按近期活跃人数锁定本阶段规模，不因战斗中途掉线立即变化。
- 后加入玩家获得个人基础工具，不重复领取队伍级奖励。
- 若玩家落在列车后方，可在安全车站使用有冷却和代价的无线电救援；战斗中或携带关键任务目标时需遵守额外限制。

### 8.3 队伍权限

默认所有队员可以驾驶、维修、接取可选任务和使用公共设施。以下高影响行为由服务器配置决定，可限制为队长/管理员或发起多数投票：

- 放弃当前强制任务并启用应急解法；
- 执行列车救援/回正；
- 拆除被标记为关键的默认列车控制；
- 切换无限模式；
- 重置章节或调用管理补偿。

MVP 不强制职业系统。可通过装备和车内工作站形成软分工。

### 8.4 联机性能原则

- 不在后方持续生成实体尸潮，使用抽象追击距离。
- 只强加载列车安全运行所需的有限区块和即将到达的线路区段。
- 城市战利品与任务目标按区块激活，远离玩家时停止高频扫描。
- 轨道连续性使用事件触发或分段缓存，不每刻扫描整条铁路。
- HUD 同步差量状态，不持续同步全部任务定义。

## 9. 失败与恢复

失败需要产生资源和时间压力，但不得轻易把数十小时存档变成死档。

### 9.1 玩家死亡

- 生活/医疗单元有效时，玩家在列车安全出生点复活。
- 列车出生点不可用时，在最近已激活车站复活。
- 死亡物资采用整合包统一的尸体/掉落规则；关键任务物品不依赖普通掉落，系统可重新生成或转移到任务箱。
- 团灭会提高关注度、消耗部分公共医疗资源或推进少量时间，但不会重置整条战役。

### 9.2 列车脱轨、卡死或结构损坏

设置“列车救援”流程：

1. 确认列车在一段时间内没有有效移动且无玩家处于危险碰撞状态；
2. 保存车厢组成和公共容器引用；
3. 将列车回正到最近通过验证的主线救援点；
4. 扣除维修材料、燃料或增加关注度作为代价；
5. 恢复驾驶权限并记录救援次数。

普通玩家不能用救援机制瞬移跳过未完成主线障碍。若列车完全损坏，可在最近激活车站通过默认列车蓝图恢复核心车组，但附加车厢和部分物资可能需要重新回收。

### 9.3 任务卡死

系统自动检查：

- 目标方块或实体是否存在；
- 关键物品是否仍可获得；
- 轨道是否存在可验证通路；
- 任务状态是否长时间无合法进展；
- 目标区块是否成功生成。

恢复顺序为：

1. 重建缺失目标或补发关键物品；
2. 切换到同任务的替代交互；
3. 开启有成本的应急旁路；
4. 标记为补偿完成并记录诊断信息。

所有强制任务至少提供一种管理员命令用于查询、修复或补偿，命令必须指定任务 ID，避免误操作整局。

### 9.4 存档与重启

- 世界保存时持久化战役日、章节、里程、追击距离、任务状态、线路区段和列车绑定。
- 状态机步骤必须幂等；重启时不能重复发奖、重复生成目标或重复推进天数。
- 正在进行的现实时间倒计时在服务器无人在线或关闭期间暂停。
- 加载时先验证当前强制任务和列车，再恢复普通随机事件。

## 10. 信息呈现

玩家应能在不阅读外部攻略的情况下回答“现在要做什么、为什么不能走、失败后怎么办”。

### 10.1 常驻信息

- 当前战役日与阶段；
- 当前里程和前进方向；
- 关注度等级与后方追击距离；
- 列车速度、燃料/动力、损伤和制动状态；
- 当前主线目标的一句话摘要。

### 10.2 任务信息

- 无线电：提前通告地点、任务和剧情；
- 站台/车内任务板：展示步骤、材料、奖励和失败条件；
- 世界标记：只标记已侦察地点和当前关键目标；
- 颜色与声音：红灯代表不可通行，黄灯代表任务进行中，绿灯代表已验证通行；
- 失败提示必须同时给出恢复路径，而不只显示“任务失败”。

### 10.3 管理与诊断

专用服务器至少需要查看以下信息的管理入口：

- 当前战役状态与活跃人数；
- 当前列车和最近安全站点；
- 已生成区段及前方生成队列；
- 当前任务 ID、状态和缺失目标；
- 安全执行任务修复、列车救援和玩家回归。

## 11. MVP 范围

### 11.1 必须实现

- Minecraft 1.21.1 NeoForge 的客户端与专用服务器均可启动；
- 单人、开放局域网、专用服务器共享相同战役逻辑；
- 世界首次进入时生成一个默认起点站和一列可驾驶的默认物理列车；
- 初始补给按队伍人数发放且不能重复领取；
- 存在连续向前扩展的通达铁路主线；
- 至少生成小型站、城市站和一种工业/货运地点；
- 实现共享战役日、里程、关注度和后方追击距离；
- 实现教学任务；
- 至少实现 3 种主线障碍：断轨、车站供电开门、清障；
- 至少实现 2 种可选任务：搜救、补给/回收；
- 任务选择确定性保存，重启后不重抽、不重复发奖；
- 至少实现玩家安全重连、关键任务物品恢复和列车救援；
- 第 90 天后保证生成最终枢纽，第 100 天能够完成最终防守并记录胜利；
- 胜利后可以继续无限生成线路。

### 11.2 暂不纳入 MVP

- 多条长期分支路线和复杂调度网络；
- 强制职业、技能树和玩家对抗；
- 完整幸存者殖民地模拟；
- 大规模动态建筑破坏；
- 为每个城市制作独立剧情；
- 跨世界/跨服务器继承列车；
- 超过 8 人的专项平衡；
- 依赖实时模拟的数千实体后方尸潮。

## 12. MVP 验收标准

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| A01 | 创建新的单人世界 | 起点站、默认列车、教学任务和一次初始补给只生成一次 |
| A02 | 单人世界开放局域网并加入第二名玩家 | 第二名玩家安全出生于队伍附近；既有任务不重置；仅获得个人加入工具 |
| A03 | 启动全新专用服务器并由 1–6 人加入 | 战役可从教学开始，所有玩家看到一致的任务、天数和信号状态 |
| A04 | 在初始化任一步骤中重启服务器 | 重新加载后继续或安全重做该步骤，不出现第二列默认列车或双份公共补给 |
| A05 | 驾驶列车持续前进多个区段 | 前方主线及时生成且连续，至少可遇到车站和城市，列车不会驶入未准备区块 |
| A06 | 触发断轨任务 | 列车收到预警；玩家可取得保底材料；修复验证后信号转绿并允许通行 |
| A07 | 触发供电开门任务 | 供电、开门和防守步骤按顺序同步；重载后门保持正确完成状态 |
| A08 | 接受或跳过可选任务 | 接受后可获得一次奖励；跳过或失败不会封锁主线 |
| A09 | 任务进行到任意状态时重启 | 任务类型、地点、进度和奖励领取状态与重启前一致 |
| A10 | 丢弃、烧毁或带走关键任务物品后死亡 | 系统能够检测并补发/替代，主线仍可完成且不能无限复制奖励 |
| A11 | 玩家在行驶中掉线并在列车离开后重连 | 玩家回到列车安全点或最近激活站点，不出生在旧区块或方块内部 |
| A12 | 列车脱轨或卡死 | 合法救援能回到最近验证轨道并收取代价；不能借此越过强制任务 |
| A13 | 所有玩家离线一段现实时间 | 再次上线后战役日、任务倒计时和追击距离没有离线增长 |
| A14 | 从 1 人增加到多人，再有人退出 | 难度按采样的活跃人数平滑调整，进行中的战斗不会瞬间剧烈变化 |
| A15 | 队伍推进至第 90–100 天 | 最终枢纽在可达前方生成；第 100 天任务可完成并正确记录胜利 |
| A16 | 通关后选择无限模式 | 原列车、物资和已探索世界保留，前方线路与随机任务继续生成 |
| A17 | 4 人专用服务器进行正常行驶和城市任务 | 无无限实体/区块增长；常规游玩服务器刻稳定，短时生成峰值可自行恢复 |

## 13. 开发顺序建议

1. 建立共享战役存档、区段 ID 和服务器同步；
2. 完成起点站与默认列车的幂等初始化；
3. 接通物理列车适配层，完成驾驶、绑定、重连和救援；
4. 接通通达铁路区段生成与连续性验证；
5. 实现统一任务状态机和断轨任务；
6. 加入车站供电开门、清障及两种可选任务；
7. 加入关注度、追击距离、人数缩放和掉线处理；
8. 制作 100 天节奏、最终枢纽与无限模式；
9. 完成专用服务器压力测试、故障注入和存档升级测试；
10. 再扩充地点模板、任务池、敌人种类与数值平衡。

## 14. 待定但不阻塞 MVP 的配置项

以下内容应做成服务端配置或数据驱动定义，先采用本文默认值：

- 战役日长度与服务器无人在线时是否暂停；
- 平衡人数上限；
- 前方预生成区段数量；
- 主线障碍间隔和同类任务冷却；
- 关注度增长/衰减、追击距离速度；
- 列车救援代价和冷却；
- 玩家死亡物资规则；
- 关键方块保护范围；
- 第 100 天后结束或默认进入无限模式；
- 具体物理列车模组、武器模组和丧尸 AI 模组的适配实现。
