# 开发路线图

## 原则

- 先验证长存档与联机稳定性，再增加内容规模；
- 世界状态只由逻辑服务器修改，单人和专用服务器走相同代码路径；
- Create 轨道是线路几何的唯一事实来源；
- 任务必须可恢复，随机事件不得让百日存档永久卡死；
- 物理火车锁定 Create Simurail；其 Alpha API 位于适配层后方，升级失败时不得
  破坏战役存档。

## M0：设计基线

- 完成玩法设计与技术架构；
- 确定 Minecraft 1.21.1 + NeoForge + Java 21；
- 建立私有 GitHub 仓库与开发分支；
- 锁定 Create Simurail `e68481d` 测试构建、来源和 SHA-256；
- 记录被排除的 Loconautics/Ferronautics 方案与通达铁路兼容风险。

## M1：可加载的战役核心

- 搭建 `lasttrain` NeoForge 模组；
- 建立服务器权威 `SavedData`；
- 保存战役阶段、天数、路线索引、初始化状态和当前任务；
- 提供 `/lasttrain status`、`start`、`advance_day` 和任务调试命令；
- 验证单人世界与无图形界面专用服务器均能加载。

## M2：起点站与默认列车

- 世界首次启动时生成唯一的起点站；
- 幂等放置起始补给，防止重启和重复进服刷资源；
- 先装配 Simurail Ponder 级物理验证车，再替换为默认机车、生活车和维修货车；
- 新加入玩家在当前列车或最近激活站点汇合；
- 提供列车丢失、翻覆和载具模组缺失时的恢复路径。

## M3：无限线路导演

- 将路线拆成确定性的连续区段；
- 在列车前方预生成并校验 2–3 个区段；
- 接入通达铁路生成结果并修补断连；
- 按路线种子安排普通站、燃料站、货场、城市和剧情枢纽；
- 保存已生成区段，保证服务器重启后结果不变。

## M4：动态任务

- 实现主线障碍和可选任务状态机；
- 首批任务：断轨修复、车站供电开门、清理堵轨物、启动水塔；
- 实现任务物品补发、超时降级方案和管理员恢复命令；
- 按在线人数缩放敌人、材料和防守时间。

当前代码切片已覆盖断轨、供电、站门、线路清障、补给回收、尸群封锁、搜救与
车厢回收；主线/可选奖励共用持久 outbox，`/lasttrain validate save` 可检查跨字段
不变量。启动水塔、完整“等待恢复/补偿完成”状态以及物理列车归位仍保留在本里程碑。

## M5：百日战役

- 接入尸潮前线、警戒值和里程进度；
- 实现五个感染阶段与第 100 天终局；
- 保证关键地点与终局组件在截止日前可获得；
- 完成单人、开放联机和专用服务器的长时间存档测试。

## 首个可玩版验收

- 1–6 名玩家可以使用同一世界完成开局；
- 离线、重连和服务器重启不会复制列车、补给或任务；
- 至少一条主线可连续推进 20 个路线区段；
- 至少 4 类任务可以完成、失败并恢复；
- 物理列车故障不会无提示摧毁整局进度；
- 服务器满载时不在后方维持大量无意义的追逐实体。
